# 마루 중개 통합관리

토지·건물 매입 고객을 상대하는 중개법인 직원용 통합관리 웹앱입니다.
엑셀·메모장·기억에 흩어져 있던 고객, 물건, 니즈 변화, 상담 기록, 할 일을 한곳에서 관리합니다.

## 지금 되는 것 (Phase 0–3)

| 영역 | 기능 |
|---|---|
| 로그인·권한 | 직원 계정 로그인, 역할별 열람 범위 (직원: 본인 담당 고객 / 팀장: 팀원·미지정 고객까지 / 관리자: 전체). 물건은 전 직원 공유 |
| 고객 | 등록·수정, 진행 단계(신규→상담→물건 제안→임장→협상→계약→잔금, 이탈), 담당자 지정, 검색·단계별 필터 |
| 니즈 변화 트래킹 | 희망 지역·물건 종류·목적·예산·면적·용도지역을 **버전으로 저장**. 변경 사유와 함께 무엇이 어떻게 바뀌었는지 타임라인으로 표시. 바뀐 게 없으면 저장하지 않음 |
| 물건 | 토지/건물 등록·수정, 지번·지목·용도지역·면적(㎡/평)·희망가·평당가 자동 계산, 상태 관리 |
| 상담 기록 | 통화·미팅·임장·문자·메모 기록, 관련 물건 연결, 최근 연락일 자동 갱신 |
| 할 일 | 고객·물건에 연결된 할 일, 마감·담당자, 지난 마감/오늘/예정 구분 |
| 대시보드 | 파이프라인 현황, 30일 이상 미연락 고객, 내 할 일, 최근 물건 |
| 감사 로그 | 로그인(실패 포함), 고객 열람·수정, 니즈 변경, 제안, 가져오기 기록 (관리자 화면) |
| 니즈 ↔ 물건 매칭 | 고객 상세에 **추천 물건**, 물건 상세에 **맞는 고객**, `/matching` 화면에 아직 제안 안 한 조합 전체. 점수(0–100)와 맞는 점·확인할 점 표시 |
| 제안 기록 | 추천에서 "제안 기록" → 상담 기록 자동 작성, 신규·상담 고객은 "물건 제안" 단계로. 고객 반응(관심/거절) 기록, 거절한 물건은 추천에서 제외 |
| 파이프라인 칸반 | `/customers/board` — 카드를 끌어 단계 변경 (모바일은 카드의 선택 상자), 30일 미연락 빨간색 |
| 엑셀 가져오기 | `/import` — .xlsx·.csv(EUC-KR 포함) 업로드 → 헤더 자동 연결 → 미리보기(오류·중복·확인 필요 행 번호) → 저장. 양식 다운로드 제공 |

### 매칭 규칙

- 고객이 **입력한 조건만** 점수에 들어갑니다. 배점: 지역 30 · 예산 25 · 종류 20 · 면적 15 · 용도지역 10
- **제외**: 물건 종류 불일치, 희망 지역 밖, 예산 상한 20% 초과
- 예산 10% 이내 초과는 60%, 20% 이내는 30% 점수. 희망가·면적·용도지역이 물건에 비어 있으면 그 항목 절반
- 지역은 "경기 화성" ↔ "경기도 화성시 장안면…" 처럼 시도 약칭·시군구 접미사를 무시하고 비교합니다
- 진행중·협상중 물건과 진행 중(잔금 완료·이탈 제외) 고객만, 그리고 **내가 볼 수 있는 고객**만 매칭합니다

### 엑셀 가져오기 규칙

- 금액: "45억", "3억5천", "4,500만", 헤더에 "(억)"·"(만원)"·"(원)" 이 있으면 그 단위. 단위 없는 숫자는 1천만 이상이면 원, 아니면 만원으로 봅니다
- 범위: "30억~50억", "30-50억", "50억 이하", "30억 이상" / 면적: "2000~3000평", 헤더에 "평"이 있으면 평
- 중복: 고객은 연락처(숫자만 비교) 또는 이름+회사명, 물건은 지번 주소(공백 무시). 기본은 중복 건너뛰기
- 직원 권한은 가져온 고객이 모두 본인 담당이 됩니다. 담당자 열의 이름이 직원 이름과 같으면 그 직원에게 배정 (팀장·관리자)
- 예전 엑셀 형식(.xls)은 지원하지 않습니다 → .xlsx 로 저장 후 업로드

## 통화 녹음 자동 요약 (Phase 3)

메뉴 **통화 녹음** 또는 고객 상세의 "통화 녹음" 카드에서 갤럭시 통화 녹음(`.m4a`, 예전 기종 `.amr`·`.3gp`)을 올립니다.
휴대폰 브라우저에서 파일 선택 → 내장 메모리 → `Recordings/Call` 폴더에서 여러 개를 한 번에 고를 수 있습니다.

1. **고객 자동 연결** — 파일명 `통화 녹음 홍길동_231124_143012.m4a` / `Call recording 010-1234-5678_…` 에서 상대(이름·번호)와 통화 시각을 읽어, 내가 볼 수 있는 고객 중 연락처(숫자 비교) 또는 이름이 정확히 한 명과 맞으면 연결합니다. 못 찾으면 "고객 연결 필요"로 남고 화면에서 고르면 됩니다.
2. **음성 인식** — OpenAI 음성 인식(기본 `whisper-1`, 한국어·부동산 용어 힌트). 25MB 넘거나 지원하지 않는 형식은 ffmpeg 로 모노 16kHz 로 줄이고 20분 단위로 나눠 보냅니다.
3. **AI 요약** — Claude(`claude-opus-5-5`, 구조화 출력)가 한 줄 제목, 핵심 요약, 매입 의지, **니즈 변경 제안**(현재 니즈와 비교), 후속 조치(“다음 주 화요일” → 실제 날짜), 언급된 물건, 다음 연락을 만듭니다. 안전 분류기 거절 시 다른 모델로 넘기는 서버 측 fallback 을 켜 두었습니다.
4. **고객 기록 반영** — 상담 기록(통화) 1건, 직원 할 일 자동 생성, 최근 연락일 갱신. 녹음 1건당 한 번만 반영됩니다.
5. **니즈 변경은 직원이 확인 후 반영** — 녹음 화면에서 변경 전/후를 보고 "고객 니즈에 반영"을 누르면 새 버전(출처: 통화 요약)으로 저장됩니다.

처리는 업로드 응답 후 서버에서 진행되고(동시 2건), 화면은 자동으로 새로 고쳐집니다. 실패하거나 서버 재시작으로 20분 넘게 멈춘 녹음은 "재처리" 버튼으로 다시 돌립니다.

**개인정보** — 음성은 OpenAI, 녹취록은 Anthropic 으로 전송됩니다. 고객 고지·동의를 받은 통화만 올리도록 화면에 안내합니다. 음성 파일은 `RECORDING_AUDIO_RETENTION_DAYS`(기본 180일) 후 자동 삭제되고 녹취록·요약은 남습니다. 녹음은 올린 본인과 그 고객을 볼 수 있는 직원만 열람할 수 있고, 업로드·열람·재생이 감사 로그에 남습니다.

**설정** — `.env.example` 의 `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `RECORDINGS_DIR`. 서버에 `ffmpeg`/`ffprobe` 가 있어야 긴 통화·`.amr` 를 처리하고 통화 길이를 표시합니다. 개발·데모는 `STT_PROVIDER=mock SUMMARY_PROVIDER=mock`.

## 로컬 실행

필요: Node.js 22+, PostgreSQL 14+

```bash
npm install
cp .env.example .env          # DATABASE_URL, TEST_DATABASE_URL 수정
npm run db:migrate            # 테이블 생성
npm run db:seed               # (선택) 데모 데이터
npm run dev                   # http://localhost:3000
```

데모 계정 (비밀번호 모두 `maru1234!`, **데모 전용 — 운영 DB에서는 시드를 실행하지 마세요**)

|---|---|
| admin@maru.local | 관리자 |
| manager@maru.local | 팀장 (영업1팀) |
| agent1@maru.local | 직원 (영업1팀) |

## 구조

```
src/
  app/
    login/                 로그인
    (app)/                 로그인 후 화면 (대시보드, customers, properties, tasks, admin)
      */actions.ts         서버 액션 — 모두 requireUser() 와 권한 확인 후 실행
  components/              공통 UI, 폼
  db/schema.ts             테이블 정의
  lib/
    auth/                  세션(해시 저장 토큰), 비밀번호(bcrypt), requireUser/requireRole
    authz.ts               열람·수정 권한 규칙 (canViewCustomer 와 SQL customerScope 가 같은 규칙)
    needs.ts               니즈 입력 파싱·버전 비교
    needs-store.ts         니즈 버전 저장 (고객 행 잠금으로 동시 저장 시 버전 충돌 방지)
    matching.ts            니즈 ↔ 물건 점수 계산 (순수 함수)
    match-queries.ts       추천 물건·맞는 고객·매칭 화면 조회
    region.ts              지역·주소 정규화
    import/                엑셀 읽기(read-file), 헤더 매칭(fields), 값 해석(values), 행 검증(validate), 중복·저장(commit)
    calls/                 통화 녹음: 파일명 해석, 저장소, 음성 인식(stt), AI 요약(summarize·prompt·summary-schema), 처리 흐름(process)
  app/api/recordings/      녹음 업로드(POST)·재생(GET, Range) — proxy 를 거치지 않고 핸들러에서 로그인 확인
    format.ts              억/만원, ㎡/평, 서울 시간 표시
drizzle/                   SQL 마이그레이션
tests/                     Vitest
```

## 운영 시 참고

- 금액은 **만원 단위 정수**, 면적은 **㎡** 로 저장합니다. 화면에서 억/만원, 평으로 바꿔 보여줍니다.
- 세션 쿠키는 httpOnly이며 DB에는 토큰의 SHA-256 해시만 저장합니다. 직원 비활성화·비밀번호 변경 시 기존 세션이 끊깁니다.
- 고객 상세를 열 때마다 감사 로그에 열람 기록이 남습니다 (개인정보 접근 추적).
- 통화 녹음 기능(Phase 3)을 붙이기 전에 고객 고지·동의, 녹음 파일 보관 기간, 외부 STT·AI 업체 처리 위탁 여부를 정해야 합니다.
